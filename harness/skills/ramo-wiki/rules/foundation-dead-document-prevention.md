# Dead-Document Prevention

Run feedback (injecting wiki content back into `run`) is deferred to a later version, but a
wiki document that cannot be *resolved at all* while feedback is unbuilt is a defect this
harness must not ship, per what an earlier version observed:

> A lesson with no `sources:` glob is never injected. Even a well-written lesson becomes a
> dead document because nothing can match it.

## Sources resolution (mechanical, inside `validate`)

- **[HARD] Every `sources[].resource` in a candidate MUST resolve to a `git`-tracked file
  in the target repository before the transaction can reach `READY`.**
  WHY: OKF v0.2 makes `sources[].resource` required per entry (deferred to that spec, not
  restated here), but a required-and-present field is not the same guarantee as a
  required-and-resolvable one — a typo'd path satisfies the former and fails the latter
  silently. This is a *decidable* property (unlike relevance, which needs a filter that
  does not exist until a later version's injection loop), so it is checked now rather than deferred with
  everything else. Enforced by `wiki_runtime.py::validate_candidate` (`_resolve_source`,
  `check: sources-resolve`): exact paths are checked with `git ls-files`; glob resources
  (containing `*`, `?`, or `[`) must match at least one tracked file.
- A `resource` under `.ramo/` can never resolve (that tree is gitignored,
  `.claude/rules/common/state-discipline.md`) — this is the same SOT-1 discriminator the
  rest of the harness already applies to citations, extended to wiki sources rather than
  invented fresh.

## Generated index language

`wiki_runtime.py commit` regenerates `wiki/index.md` on every publish. It is Korean, not
English, even though the script that writes it is an English harness asset —
**a generated index inherits the language of what it catalogs, not the language of its
generator** (`.claude/rules/common/language-settings.md`, same precedent this repository
already applies to `docs/index.md`). An earlier version hit exactly the opposite failure: a
runtime-generated index in the deliverable language got rejected by the harness's own
language-rule linter, which was reading "generated by an asset" as "must be English" —
the precedent this file states is what prevents that reappearing here.

## What this section does not cover

Relevance filtering (which lessons actually get injected into a `run` invocation, through a
three-stage injection filter) is deferred to a later version.
This section only guarantees a document *can* be found later — not that it *will* be
surfaced at the right moment. Conflating the two would mean shipping the harder problem
now to justify not shipping the easy one.
